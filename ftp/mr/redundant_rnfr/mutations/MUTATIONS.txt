FTP REDUNDANT RNFR - MUTATIONS SUMMARY
================================================================================

Metamorphic Relation:
  Multiple RNFR commands before RNTO should work correctly.
  Last RNFR determines which file gets renamed.

Validation Points:
  1. RNTO response codes match between sessions (A: single RNFR, B: multiple RNFR)
  2. Renamed directories appear in LIST output for both sessions

================================================================================
MUTATIONS IMPLEMENTED (5 + 1 BASELINE)
================================================================================

[BASELINE]
  Description: Clean baseline - normal RNFR/RNTO behavior
  Expected: 0 violations (all tests pass)
  Detection: N/A

[M1] FIRST_RNFR_WINS
  Category: State Management
  Bug: Only first RNFR is stored; subsequent RNFRs are silently ignored
  Implementation: Store first RNFR target, respond "350" to later RNFRs but don't update state
  Expected Violation: Session B tries to rename testdir_b, but first RNFR was also testdir_b
                      Since "last RNFR wins" is violated, renamed directory may not appear
  Detection: LIST verification fails to find target_name_b

[M2] REJECT_REDUNDANT_RNFR
  Category: State Management
  Bug: Second and subsequent RNFR commands return error code (503 Bad sequence)
  Implementation: Track if RNFR was called, return 503 on subsequent calls
  Expected Violation: Session B's second RNFR returns 503, RNTO may fail or behave unexpectedly
  Detection: RNTO response codes differ (A=250, B=5xx or 503)

[M3] CLEAR_STATE_ON_RNFR
  Category: State Management
  Bug: Each RNFR clears the pending rename state instead of updating it
  Implementation: Set fs.rnfr = None before and after processing RNFR
  Expected Violation: Final RNTO fails because no pending rename exists (state was cleared)
  Detection: RNTO response code differs (A=250, B=503 "Bad sequence of commands")

[M5] RENAME_WRONG_TARGET
  Category: Execution
  Bug: RNTO renames a different directory instead of the RNFR target
  Implementation: Append "_wrong" to fs.rnfr before executing RNTO
  Expected Violation: RNTO tries to rename non-existent source, fails or renames wrong dir
  Detection: LIST verification fails (target_name_B not found), or RNTO returns error code

[M6] WRONG_RNTO_SUCCESS_CODE
  Category: Execution / Response Code
  Bug: RNTO operation succeeds and renames correctly, but returns wrong success code
  Implementation: Perform actual rename, but respond "200" instead of "250"
  Expected Violation: Response codes differ between sessions even though operations succeed
  Detection: codeA != codeB (A=250 "Renaming ok", B=200 "Renaming ok")

================================================================================
MUTATION SCORE CALCULATION
================================================================================

Total Mutations: 5 (excluding BASELINE)
Expected Killed: 5 (100%)

Formula: Mutation Score = (Killed / Total) × 100%

A mutation is "killed" if:
  - violations > 0 (detected by metamorphic constraint), OR
  - status == "ERROR" (test crashed/failed)

A mutation "survives" if:
  - violations == 0 AND status == "OK"
